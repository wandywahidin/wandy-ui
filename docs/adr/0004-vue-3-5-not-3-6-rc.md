# ADR 0004: Target Vue 3.5, not the 3.6 release candidate

- **Status:** Accepted
- **Date:** 2026-11-19

## Context

Vue 3.6 (with Vapor Mode) was still a release candidate when this library started (October–November 2026). Vue 3.5 is the current stable line, and it already includes what the library needs: `defineModel`, `useId()` for SSR-stable ids, `useTemplateRef`, and reactive props destructure.

A component library sets the _floor_ for its consumers. Whatever we require, every consuming app must run.

## Decision

Target **Vue `^3.5`** (peer dependency) and test against the latest stable 3.5.x. Don't use Vapor Mode or any 3.6-only API.

## Alternatives

| Option                 | Why not                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Target 3.6 RC          | RC APIs can still change, and requiring an RC forces every consumer onto pre-release Vue.                                                               |
| Support Vapor Mode now | Vapor is opt-in per component and still settling. Reka UI, our dependency for four components, would have to support it first.                          |
| Support Vue 3.3/3.4    | We'd lose `useId()` (needed for collision-free ids across multiple instances and SSR) or have to polyfill it, and `defineModel` would need workarounds. |

## Consequences

- Apps on Vue 3.5+ can adopt the library today; 3.6 apps keep working because 3.6 is backward compatible with 3.5's APIs.
- Once 3.6 is stable, adding Vapor-compatible builds is a minor release, recorded in a new ADR.
- Raising the Vue floor later is a breaking change for consumers and goes through the Versioning rules.
